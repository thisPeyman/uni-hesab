# بسته گزارش و ارائه «حساب»

این پوشه، گزارش نهایی **26 صفحه‌ای A4** و ارائه تصویری **18 اسلایدی 16:9** پروژه را با منابع قابل ویرایش در بر دارد. هویت بصری با برنامه هماهنگ است: سبز حساب، زمینه روشن، قلم محلی Vazirmatn و نوار تفکیک پول. تعداد صفحه گزارش پس از ویرایش گسترده متن ممکن است تغییر کند.

## 1. تکمیل مشخصات جلد

فایل [`project.json`](project.json) را ویرایش کنید. برای تمام این موارد جای مشخص وجود دارد:

- نام و نام خانوادگی دانشجو؛
- نام استاد؛
- عنوان درس؛
- شماره دانشجویی؛
- شماره ترم / نیمسال تحصیلی؛
- نام دانشگاه / دانشکده و تاریخ ارائه شمسی.

شماره دانشجویی را به شکل رشته داخل کوتیشن نگه دارید تا صفر ابتدای آن حذف نشود. سپس از **ریشه پروژه** اجرا کنید:

```bash
uv run docs/build_documents.py
```

این فرمان، گزارش و اسلایدها را از Markdown و CSS می‌سازد و خروجی PDF و HTML را در `docs/output/` می‌نویسد. فایل‌های خروجی را مستقیم ویرایش نکنید؛ در ساخت بعدی بازنویسی می‌شوند. یادداشت سخنران نیز از توضیح‌های `<!-- notes: ... -->` در منبع اسلاید تولید می‌شود.

وابستگی‌های مخصوص سند با PEP 723 در اسکریپت مشخص شده‌اند و به وابستگی‌های برنامه اضافه نمی‌شوند. نصب نخست ممکن است اینترنت بخواهد؛ پس از cacheشدن، `uv run --offline docs/build_documents.py` قابل استفاده است. در شبکه محدود می‌توانید همان پراکسی SOCKS معرفی‌شده در README اصلی را به uv بدهید.

برای خروجی PDF به Google Chrome یا Chromium نیاز است. در صورت تشخیص‌ندادن خودکار:

```bash
uv run docs/build_documents.py --chrome /path/to/chrome
```

برای ساخت فقط HTML و Markdown، بدون اجرای مرورگر:

```bash
uv run docs/build_documents.py --html-only
```

ساخت سند نیازی به اجرای Streamlit ندارد و فایل‌های مالی را نمی‌خواند. فایل HTML خروجی، قلم و تصاویر را در خود دارد؛ می‌توانید آن را مستقل منتقل کنید. PDF گزارش دارای شماره صفحه و PDF ارائه دقیقاً 18 صفحه عریض است.

## 2. خروجی با افزونه Markdown PDF در VS Code

1. مشخصات را در `project.json` تکمیل و فرمان ساخت بالا را اجرا کنید؛ یا در صورت نبود Chrome از `--html-only` استفاده کنید.
2. فایل [`hesab-report.code-workspace`](hesab-report.code-workspace) را در VS Code باز کنید. تنظیمات مخصوص چاپ فقط در همین workspace اعمال می‌شوند.
3. افزونه **Markdown PDF** با شناسه `yzane.markdown-pdf` را نصب کنید.
4. `docs/output/project-report.md` را باز کنید. این نسخه بر خلاف منبع، متغیر جایگذاری‌نشده ندارد و مسیر CSS و تصاویر آن برای همین پوشه تنظیم شده است.
5. از Command Palette فرمان **Markdown PDF: Export (pdf)** را اجرا کنید. اندازه A4، پس‌زمینه چاپی، حاشیه‌ها و CSS محلی از قبل آماده‌اند.
6. در صورت تفاوت نسخه Chromium افزونه، خروجی را از نظر شکست صفحه، راست‌به‌چپ و قلم بررسی کنید. **PDF تولیدشده توسط `build_documents.py` خروجی مرجع و بررسی‌شده این بسته است.**

قالب از HTML درون Markdown، جدول و CSS چاپ استفاده می‌کند. برای این بخش‌ها باید رندر HTML مجاز باشد. متادیتای ابتدای منبع اصلی توسط سازنده حذف می‌شود؛ نسخه آماده مخصوص افزونه بدون آن تولید می‌شود. اگر فقط یک فایل Markdown را جابه‌جا کنید، قلم، CSS و عکس‌ها همراهش نخواهند بود؛ برای انتقال تک‌فایلی از HTML یا PDF آماده استفاده کنید.

برای اسلایدها، A4 انتخاب نکنید. از PDF آماده یا HTML ارائه استفاده کنید؛ خروجی مرجع با اندازه `1280 × 720` پیکسل و حاشیه صفر ساخته می‌شود.

## 3. ارائه در مرورگر

`docs/output/presentation.html` را باز کنید. حالت عادی همه اسلایدها را برای مرور پشت سر هم نشان می‌دهد. برای حالت نمایش، `?present` را به آدرس فایل اضافه کنید یا کلید `P` را بزنید.

| کلید | رفتار |
|---|---|
| `←`، `PageDown` یا Space | اسلاید بعدی |
| `→` یا `PageUp` | اسلاید قبلی |
| `Home` / `End` | اسلاید اول / آخر |
| `P` | جابه‌جایی بین مرور و نمایش تک‌اسلاید |
| `F` | تمام‌صفحه مرورگر |
| `Escape` | خروج از حالت تک‌اسلاید |

ارائه کامل برای حدود **10 تا 14 دقیقه** مناسب است. تصاویر محصول با توضیح فنی تبدیل ورودی، انتخاب نسخه بودجه، تاریخچه تخصیص، قیود داده و چرخه ارسال فرم همراه‌اند. برای 5 تا 7 دقیقه، بعضی تصاویر محصول را سریع مرور کنید و اسلایدهای معماری، مدل داده و چرخه اجرا را نگه دارید. یادداشت هر اسلاید در `presentation/SPEAKER_NOTES.md` است و در PDF یا روی پرده نشان داده نمی‌شود. منبع علمی و شرح کامل محدودیت‌ها در گزارش آمده است.

نوار پایین، نسبت **شماره اسلاید به تعداد کل اسلایدها** را نشان می‌دهد؛ در اسلاید اول `1/18` و در اسلاید آخر `18/18` است. نسبت در زمان ساخت برای هر صفحه محاسبه می‌شود تا HTML و PDF رفتار یکسان داشته باشند. بررسی خودکار نوار، ترتیب شماره‌ها، کلیدهای نمایش و محدوده امن چیدمان:

```bash
uv run tests/browser_presentation.py
```

## 4. بازتولید تصاویر

شش تصویر واقعی در `assets/` موجودند: نمای کلی، تراکنش‌ها، فرم ثبت، بودجه، هدف و تنظیمات. برای گرفتن مجدد تصاویر:

```bash
uv run streamlit run app.py
```

در ترمینال دوم:

```bash
uv run docs/capture_screenshots.py
uv run docs/build_documents.py
```

اسکریپت تصویر فقط حالت نمایشی را باز می‌کند، صفحات و فرم را می‌بیند و **هیچ تراکنش، بودجه، هدف یا تخصیصی ذخیره نمی‌کند**. رفتار طبیعی برنامه این است که اگر پایگاه داده نمایشی هنوز افتتاح نشده باشد، داده ساختگی اولیه را در همان فایل مستقل بسازد. داده نمایشی موجود بازنشانی نمی‌شود. هیچ فایل شخصی یا نمایشی را برای تازه‌کردن تصویر حذف نکنید. مسیر Chrome در اسکریپت تصویر فعلاً `/usr/bin/google-chrome` است؛ در سیستم دیگر آن را متناسب ویرایش کنید.

داده‌های نمایشی به روز اجرا وابسته‌اند، بنابراین ارقام تصاویر ممکن است در اجرای جدید عوض شوند. مثال‌های عددی داخل متن، مثال آموزشی‌اند و به مقادیر زنده وابسته نیستند.

## 5. محتوای گزارش

گزارش شامل چکیده، نیازمندی‌ها، مدل مالی، معماری، چرخه Streamlit، ERD، فرهنگ داده هفت جدول، قیود، DDL کامل، الگوریتم بودجه و موجودی، تاریخ شمسی، قفل و تراکنش SQLite، امنیت، پشتیبان و بازیابی، راهنمای تصویری، آزمون‌ها، نصب و عیب‌یابی، محدودیت‌ها، ردگیری نیازمندی و منابع است. توضیح‌ها قابلیت موجود را از پیشنهاد آینده و قید SQLite را از اعتبارسنجی برنامه جدا می‌کنند.
