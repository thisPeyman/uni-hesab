# سناریوی کوتاه ارائه

## پیش از ارائه

- `uv sync` را با اینترنت اجرا کنید؛ برنامه پس از نصب به اینترنت نیاز ندارد.
- `uv run pytest` را اجرا کنید.
- `uv run streamlit run app.py` را اجرا و مرورگر را در اندازه لپ‌تاپ باز کنید.
- حالت نمایشی را روشن کنید؛ نشان زرد «حالت نمایشی» باید مشخص باشد.
- برای داده نمایشی تازه، فقط پس از توقف برنامه، فایل `data/demo.sqlite3` را به نام دیگری منتقل کنید؛ به فایل شخصی دست نزنید.

## ارائه ۴ تا ۶ دقیقه‌ای

1. **مسئله:** ثبت ساده درآمد/هزینه با تقویم شمسی و تفکیک پول قابل خرج از پس‌انداز.
2. **نمای کلی:** تفاوت موجودی کل، پول کنارگذاشته‌شده و پول قابل خرج را توضیح دهید. فیلتر ماه را تغییر دهید؛ موجودی کل ثابت می‌ماند اما آمار ماه تغییر می‌کند.
3. **تراکنش:** هزینه کوچکی برای خوراک ثبت کنید؛ تغییر آمار و نمودار را نشان دهید. همان تراکنش را جست‌وجو و ویرایش کنید.
4. **بودجه:** سقفی برای خوراک بگذارید. تفاوت «از این ماه به بعد» با «فقط همین ماه» و هشدار عبور از سقف را توضیح دهید.
5. **هدف:** مبلغی برای لپ‌تاپ کنار بگذارید. نشان دهید موجودی کل ثابت است اما پول قابل خرج کم می‌شود. بخشی را آزاد کنید.
6. **داده:** CSV و پشتیبان کامل را معرفی کنید؛ حالت نمایشی و شخصی فایل‌های جدا دارند.
7. **فنی:** UI از منطق مالی جداست؛ SQLite با کلید خارجی و تراکنش اتمیک، تاریخ ISO داخلی با مرز گزارش شمسی، مبلغ صحیح بدون float.

## پاسخ‌های آماده به پرسش‌های فنی

- **چرا Streamlit؟** سرعت توسعه و رابط تعاملی با Python برای پروژه کوچک محلی، بدون نیاز به frontend/backend جدا.
- **چرا SQLite؟** پایگاه داده پایدار و تراکنشی بدون نصب سرور برای یک کاربر.
- **چرا تاریخ داخلی میلادی است؟** استاندارد ISO مرتب‌سازی و مقایسه را مطمئن می‌کند؛ نمایش و بازه‌بندی کاملاً شمسی است.
- **چرا مبلغ integer است؟** جلوگیری از خطای اعشار شناور و هماهنگی با تومان صحیح.
- **چرا هدف هزینه نیست؟** جابه‌جایی ذهنی پول موجود است، نه خروج پول؛ خرج واقعی جدا ثبت می‌شود.
- **چه محدودیت‌هایی دارد؟** محلی و بدون رمزگذاری/احراز هویت؛ فاقد اتصال بانک، ورود CSV، برنامه‌ریزی تراکنش و چند حساب.
