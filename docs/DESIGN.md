# طرح حساب

## هدف و محدوده

یک برنامه تک‌کاربره، محلی، فارسی و راست‌به‌چپ برای ثبت درآمد و هزینه، بودجه‌بندی ماهانه و کنارگذاشتن پول برای هدف‌ها. واحد تمام مبالغ **تومان صحیح** است؛ اعداد در رابط انگلیسی و تمام تاریخ‌های قابل مشاهده شمسی هستند.

## هویت بصری

- کاغذ: `#F7F6F2`
- جوهر: `#18382E`
- سبز اصلی: `#17654B`
- سبز روشن ذخیره: `#B4BF8E`
- خاکستری متن فرعی: `#718078`
- هشدار: `#B17B32`

قلم متن و عنوان فارسی: Vazirmatn، با وزن سنگین برای عنوان و وزن معمول برای متن؛ اعداد با فاصله ثابت و جهت چپ‌به‌راست. قلم از فایل محلی بارگذاری می‌شود، نه سرویس بیرونی.

نشانه متمایز طرح، نوار تخصیص پول است: کل پول به بخش «قابل خرج» و «کنارگذاشته‌شده» تقسیم می‌شود. این نوار یک مفهوم مالی واقعی را بیان می‌کند و تزئین نیست. کارت‌های آمار و نمودارها در نقش فرعی می‌مانند.

```text
                 نمای کلی                 | حساب
 ماه انتخاب‌شده و ثبت سریع                | نمای کلی
 ┌─────────────────────────────────────┐  | تراکنش‌ها
 │ کل موجودی                           │  | بودجه‌ها
 │ [ قابل خرج        | ذخیره هدف‌ها ]   │  | هدف‌ها
 └─────────────────────────────────────┘  | تنظیمات
 [درآمد ماه] [هزینه ماه] [خالص ماه]        |
 [هزینه به تفکیک دسته] [وضعیت بودجه]       | حالت نمایشی
 [آخرین تراکنش‌ها]                        | فقط روی دستگاه شما
```

## قواعد دامنه

- موجودی = موجودی اولیه + درآمدها − هزینه‌ها.
- ذخیره = مجموع خالص تخصیص/آزادسازی هدف‌ها.
- قابل خرج = موجودی − ذخیره. امکان منفی شدن در اثر ثبت واقعیت وجود دارد و هشدار نمایش داده می‌شود.
- تخصیص جدید نمی‌تواند از پول قابل خرج یا مبلغ باقی‌مانده هدف بیشتر باشد.
- آزادسازی نمی‌تواند از ذخیره همان هدف بیشتر باشد.
- تخصیص هدف هزینه نیست؛ تکمیل هدف خرید ایجاد نمی‌کند. قبل از تکمیل یا بایگانی، پول هدف باید آزاد شود.
- بودجه هزینه‌های یک دسته را در ماه شمسی می‌شمارد؛ تخصیص هدف و موجودی اولیه در آن نیست.
- قانون تکرارشونده از ماه اثرگذاری تا قانون بعدی معتبر است؛ تغییر آن ماه‌های قبل را بازنویسی نمی‌کند. استثنای ماهانه اولویت بالاتر دارد.
- سقف صفر یعنی اجازه هزینه صفر؛ نبود سقف یعنی بودجه تنظیم نشده است.
- بایگانی دسته تاریخچه را حذف نمی‌کند. ویرایش تراکنش قبلی با دسته بایگانی‌شده مجاز است، ثبت جدید نیست.

## معماری و پایگاه داده

`app.py` و `hesab/ui.py` فقط نمایش و مدیریت رویدادهای رابط هستند. `hesab/store.py` تمام عملیات اعتبارسنجی و مالی را مستقل از Streamlit انجام می‌دهد. `hesab/dates.py` مرز تبدیل تاریخ را نگه می‌دارد.

| جدول | مسئولیت |
|---|---|
| settings | تاریخ و مبلغ افتتاحیه، فقط یک رکورد |
| categories | نام، نوع درآمد/هزینه، وضعیت بایگانی |
| transactions | تاریخ ISO، نوع، مبلغ صحیح، دسته و توضیح |
| budget_rules | نسخه‌های بودجه به تفکیک دسته و ماه اثرگذاری |
| budget_overrides | سقف استثنایی یک دسته در یک ماه |
| goals | عنوان، مبلغ هدف، مهلت اختیاری، وضعیت |
| goal_entries | تاریخچه تخصیص مثبت و آزادسازی منفی |

روابط: هر دسته چند تراکنش و چند قانون بودجه دارد؛ هر هدف چند ورودی تخصیص دارد. کلیدهای خارجی فعال هستند. عملیات بررسی و تخصیص داخل `BEGIN IMMEDIATE` انجام می‌شود تا دو تب هم‌زمان نتوانند یک موجودی را دوبار تخصیص دهند.

تاریخ‌ها برای مرتب‌سازی مطمئن به صورت Gregorian ISO در SQLite ذخیره می‌شوند؛ ورودی، نمایش و بازه گزارش‌ها شمسی است. بازه‌ها به شکل `[ابتدای ماه، ابتدای ماه بعد)` هستند تا اسفند کبیسه درست محاسبه شود.

## امنیت و محدودیت

فایل‌های شخصی و نمایشی جدا هستند. SQLها با پارامتر اجرا می‌شوند و متن کاربر قبل از قرارگرفتن در HTML escape می‌شود. CSV از BOM برای سازگاری فارسی و محافظت اولیه در برابر فرمول صفحه‌گسترده استفاده می‌کند. نسخه پشتیبان با API خود SQLite از یک snapshot سازگار تهیه می‌شود.

برنامه احراز هویت یا رمزگذاری ندارد و فقط برای localhost است. کسی که به فایل‌ها دسترسی داشته باشد می‌تواند اطلاعات را بخواند. ورود CSV، بازیابی از داخل رابط، چند حساب، تکرار خودکار، اتصال بانک و استقرار عمومی جزو این نسخه نیستند.
